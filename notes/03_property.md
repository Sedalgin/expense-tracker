# `@property` — свойство

## Что это
Атрибут, который снаружи выглядит обычным (`expense.amount`), а внутри при чтении и записи вызываются **твои методы**.
- **геттер** (getter) — срабатывает при чтении `obj.amount`;
- **сеттер** (setter) — срабатывает при записи `obj.amount = ...`.

## Зачем
Без свойства проверку можно обойти:
```python
expense = Expense("Кофе", 50)
expense.amount = -100       # без @property — ошибки нет!
```
С `@property` проверка срабатывает **на любом** `=`.

## Код из проекта (`expense.py`)
```python
class Expense:
    def __init__(self, category, amount):
        self.category = category
        self.amount = amount              # ← идёт через сеттер!

    @property
    def amount(self):                     # геттер
        return self._amount

    @amount.setter
    def amount(self, new_amount):         # сеттер
        if new_amount <= 0:
            raise ValueError("Сумма должна быть больше нуля")
        self._amount = new_amount         # сначала проверка, потом запись

    def change_amount(self, new_amount):
        self.amount = new_amount          # через свойство, не через _amount
```

## Три имени — три роли
| Имя | Роль |
|---|---|
| `amount` | **дверь** — через неё все читают и пишут |
| `_amount` | **сейф** — где число реально лежит |
| `new_amount` | просто имя параметра |

## Все дороги — через сеттер
```
__init__        ─┐
change_amount   ─┼──► сеттер (проверка) ──► _amount
obj.amount = …  ─┘
```
Правило «сумма > 0» записано **один раз**.

## Правила
1. Геттер и сеттер называются **одинаково** — как свойство (`amount`).
2. `_amount` трогают **только** геттер и сеттер. Все остальные (даже методы класса) — через `amount`.
3. `return self.amount` в геттере → геттер вызывает сам себя → `RecursionError: maximum recursion depth exceeded`.
4. Сначала `raise`, потом запись — тогда при ошибке старое значение не портится.

## Термины
- **Инкапсуляция** (encapsulation) — данные спрятаны, доступ только через «дверь» с проверкой. Одна из основ ООП.
- **Рекурсия** — функция вызывает саму себя.
- **Обратная совместимость** — старый метод (`change_amount`) оставили, чтобы не сломать код, который его вызывает.

## ❓ Вопрос с собеседования
**Что такое `@property` и зачем он нужен?**
<details><summary>Ответ</summary>

Превращает атрибут в пару методов. Сеттер проверяет значение при записи и кладёт его во внутреннее поле `_amount`, геттер отдаёт при чтении. Внешний код работает через `amount` и не знает, как оно хранится — можно добавить проверку, не меняя код, который использует класс.
</details>
