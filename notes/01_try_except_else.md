# try / except / else и `as e`

## Что это
Способ поймать ошибку (исключение, exception), чтобы программа не упала, а вежливо ответила пользователю.

```python
try:
    ...           # код, который МОЖЕТ упасть
except ValueError as e:
    ...           # выполняется, если упал. В e — текст ошибки
else:
    ...           # выполняется, если НЕ упал
```

## Зачем
- `try` — только строки, которые реально могут упасть. Чем меньше `try`, тем понятнее, какую ошибку ловим.
- `else` — «спокойный» код после успеха (сохранение, печать).
- ⚠️ Ошибка внутри `else` **не ловится** этим же `except`.

## Чей текст в `e`
`e` содержит текст **того, кто выбросил ошибку**.

| Кто упал | Текст в `e` |
|---|---|
| `int("abc")` | Python: `invalid literal for int() with base 10: 'abc'` |
| `raise ValueError("Сумма должна быть больше нуля")` | твой текст |

Поэтому: для `int()` — своё сообщение, для своего класса — `print(e)`.

## Два шлагбаума (из `main.py`)
```
текст ──► [ int() ] ──► число ──► [ Expense ] ──► OK
              │                        │
        не число?                 число <= 0?
              ▼                        ▼
         текст Python             текст класса
```
Если первый шлагбаум закрыт — до класса дело не доходит.

```python
try:
    value = int(input("Сумма: "))
except ValueError:
    print("Надо ввести число")
else:
    try:
        expense = Expense(key, value)
    except ValueError as e:
        print(e)
    else:
        general_list.append(expense.to_dict())
```

## Что принимает `int()`
| Ввод | Результат |
|---|---|
| `"007"` | `7` (ведущие нули — ок) |
| `"  7  "` | `7` (пробелы по краям — ок) |
| `"+5"`, `"-0"` | `5`, `0` |
| `"2.5"` | ❌ ошибка (дробь — это `float`) |
| `"1 000"`, `"5О"` (русская О), `""`, `"-"` | ❌ ошибка |

**Граничные значения:** всегда проверяй `-1`, `0`, `1`. Условие `<= 0` — ноль тоже ошибка.

## ❓ Вопрос с собеседования
**Что выполнится, если в `try` не было ошибки: `except` или `else`?**
<details><summary>Ответ</summary>

`else`. `except` — только при ошибке.
