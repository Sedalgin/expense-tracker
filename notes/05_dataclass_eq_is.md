# `dataclass`, `==` и `is`

## Что такое dataclass
Декоратор из стандартной библиотеки. Перечисляешь поля с типами — он **сам генерирует** `__init__`, `__repr__`, `__eq__`.

```python
from dataclasses import dataclass

@dataclass
class StockItem:
    name: str
    quantity: int

    def __post_init__(self):          # проверки — здесь, а не в __init__
        if self.quantity < 0:
            raise ValueError("Остаток не может быть меньше нуля")
```
```python
item = StockItem("Кофе", 3)
print(repr(item))                     # StockItem(name='Кофе', quantity=3)
item == StockItem("Кофе", 3)          # True
```

## Зачем
1. **Меньше кода → меньше ошибок.** Новое поле — одна строка, а не правки в 4 местах (`__init__`, `__repr__`, `__eq__`).
2. **Читается как «паспорт данных»** — сразу видно поля и типы.
3. **Удобно в тестах:** `assert item == StockItem("Кофе", 3)`.
4. **Подготовка к FastAPI** — там данные описываются так же (Pydantic `BaseModel`).

## Важно знать
- `name: str` — **аннотация типа** (type hint). Python её **не проверяет**: `StockItem("Кофе", "три")` создастся.
- Свой `__init__` не пишут — для проверок есть `__post_init__` (вызывается сразу после сгенерированного `__init__`).
- `__post_init__` проверяет **только при создании**. `item.quantity = -5` пройдёт. Нужна защита при каждой записи → `@property` (поэтому `Expense` остался обычным классом).
- Методы, которые ты написал сам (`__str__`), dataclass **не трогает**.

## `==` и `is`
- `==` — **одинаковые ли данные?** (вызывает `__eq__`)
- `is` — **тот же самый ли объект?** (сравнивает адрес в памяти, `id()`)

```python
a = StockItem("test", 1)
b = StockItem("test", 1)   # второй, отдельный объект
a == b      # True  (dataclass сравнивает поля)
a is b      # False (два разных объекта)
```

**Почему без dataclass `a == b` → `False`:** если у класса нет `__eq__`, Python не знает, что считать «одинаковым», и `==` работает как `is` — сравнивает адреса. Адреса разные → `False`.

`is` используют почти только с `None`: `if result is None:`.

## `=` не копирует
```python
a = StockItem("Кофе", 3)
b = a              # второе ИМЯ для того же объекта, копии нет
b.quantity = 10
a.quantity         # 10
```
То же со списками: `delete_expenses(general_list)` меняет **тот же** список, что в `main()`. Настоящая копия — `old_list.copy()` или `copy.copy(obj)`.

## ❓ Вопросы с собеседования
**1. Чем `==` отличается от `is`?**
<details><summary>Ответ</summary>

`==` сравнивает данные (через `__eq__`), `is` — что это один и тот же объект в памяти.
</details>

**2. Что генерирует `@dataclass`?**
<details><summary>Ответ</summary>

`__init__`, `__repr__`, `__eq__` по списку полей. Проверки — в `__post_init__`.
</details>
